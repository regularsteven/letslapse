# lut-spike — `.cube` LUTs through Core Image, on the engine's own renders

The proof of concept behind `docs/presets-lut-spike.md` (2026-09-08). A
standalone macOS Swift file, no package: it parses `.cube` files, applies them
with the built-in `CIColorCubeWithColorSpace` filter (sRGB lookup space), and
lays out three contact sheets — the photo × LUT matrix, one photo × every LUT,
and one LUT × every photo as before/after pairs.

It deliberately takes **engine renders** as its photos, not raw files: raw
goes through `LinearFrameDecoder` + `GradeEngine` exactly as the app renders
it, via the CLI, and the LUT sits on that output — which is where a LUT stage
would sit in the app (`EnginePostPasses`, after dehaze and HSL).

```bash
# 1. Build the Kit's CLI if needed (Kit/.build/debug/lapse).
# 2. Engine-neutral renders of the frames you want to judge on:
lapse grade /Volumes/letslapse/Projects/<id>/source/_WEX4119.ARW --recipe '{}' --out engine/arw-4119.jpg --scale 0.15
lapse grade /Volumes/letslapse/Projects/<id>/source/frame-02182.dng --recipe '{}' --out engine/dng-02182.jpg --scale 0.25
# 3. Build and run the spike:
swiftc -O -o lutspike lutspike.swift
./lutspike <outDir> <dir-of-.cube-files> <hero.jpg> <frame.jpg>...
```

Output: `matrix-frames-x-luts.png`, `usecase2-one-photo-many-luts.png`,
`usecase1-one-lut-many-photos.png`, and a console report per LUT — size,
parse time, value range, and where it sends black, 18 % grey, 50 % grey and
white (a log-input LUT crushes 18 % grey toward black; none of the eight
tested do).

Traps met and fixed here, worth keeping when this becomes Kit code:

- **CRLF files never split.** Swift's `Character` treats `"\r\n"` as ONE
  grapheme, so splitting on `== "\n" || == "\r"` matches nothing and the
  whole file reads as zero data rows. Split on `Character.isNewline`. Four of
  the eight files on the Desktop are Windows-ended.
- **`TITLE` is not a name.** Five of the eight say `"Generated by Resolve"`.
  Name a LUT after its file.
- **Values outside 0…1 happen** (CAPEA: −0.053…1.007). The filter takes
  floats, so pass them through and let the 8-bit readback clip.
- `CIColorCubeWithColorSpace` takes RGBA float32, red varying fastest — the
  `.cube` order, no reshuffle — and its dimension limit is 2…128 (checked on
  macOS 15), so 17/25/33/64/65 all load.
- `CIImage(contentsOf:)` of a raw would use Apple's default rendering, which
  is NOT the app's picture; that is why the frames come in as engine JPEGs.
