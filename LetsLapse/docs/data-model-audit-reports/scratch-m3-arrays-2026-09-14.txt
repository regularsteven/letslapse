  A first launch on a 10k root with no export regenerates it once: 3.2 s on the queue, a 73 MB JSON tree in flight (340 MB peak).

  The Projects list: macOS SwiftUI `List` instantiates every row's card — and its thumbnail — eagerly, whatever the ids cost (a
  search narrowed to 55 rows after the first pass still held 419 MB, because the first pass had built 10,000). The store and index
  side is flat (the Gallery proves it: the same records, a LazyVGrid). The fix is the brief's own M2 wording, "lists take pages": a
  paged ForEach that renders the first N rows and extends on scroll — a visible behaviour change past N projects, so a design call,
  not done here.

  What the export cost before W4: `readLibraryExport` parsed the whole file for the marker and the id sets — 73 MB at 10k, +270 MB
  resident on the Create tab. Now the marker and the record counts are read from the file's last kilobyte
  (`LibraryExportFormat.readTrailer`), and staleness is decided by counts against the index.
