# iOS (iPhone) design specs

Canvas 393×852 pt (iPhone 16/17 class). One file per screen per orientation; variants in the filename. Status: ✅ Synced · ⚠️ Stale · 🟡 Planned (not yet drawn).

Last full sync: 2026-08-05 (later same day), working tree of `ios-app` — **video-card source line on Projects**: a video project's card now states its source make-up on a second secondary line under the format line — "N source clips" (an import reads "1 source clip"), extended with "· N bursts at R fps" when the shoot's `sequence.json` records segments above the base rate (one burst reads "1 burst at…", mixed rates collapse to a range, "120–240 fps"). Data behind it: `AppModel.BurstClipSummary` + `burstClipSummary(for:)`, a cached `MediaWorkQueue` read of the sidecar — zero-count answers are cached too, so scrolling never re-probes an import — and `ProjectCard.sourceLine` composes the text, loading the burst tail in its own `.task` and keeping what is on screen when a read is cancelled. Video-kind only, by design: interval cards already count their photos in the format line (and cannot carry bursts — marker-mode intervals are intent at the base rate, not burst clips), and a Photo-mode capture stays ONE asset. Card 1 in [projects.portrait.svg](projects.portrait.svg) grew 16pt for the line; the same edit fixed two content drifts (card 1's missing "Video ·" prefix, card 2's stale "DNG · 10-frame blend" line → "Interval · 184 photos"). Verified on the iPhone 17 Pro sim via a seeded fixture library + `LL_TAB=projects`: live shoot → "4 source clips · 2 bursts at 120 fps" (and the 120–240 range with a mixed sidecar), import → "1 source clip", interval and photo cards unchanged. Previous sync earlier the same day — **Apple Vision as a built-in model**: the catalog gained a zero-download entry (`engine: "vision-framework"`) that skips the whole download/disk/memory state machine and is ready the moment the app launches; a fresh install adopts it automatically, an installed VLM still wins where there is one. The AI Models screen's first section is therefore no longer "Downloaded" but **"On this device"**, carrying an *Apple Vision · INSTANT* row ("Built-in · always available", no size, no Download button, no delete swipe or context menu) above the downloaded models, and its header copy now leads with what works for free. TurboQuant is gone from the catalog entirely (a shape mismatch no engine here can load). Vision tags but cannot name, so the Auto rename & tag row says so while it is active, and its proposal opens on the project's current name instead of a blank field. New projects are tagged **silently at capture time** when Vision is the active model (one frame, no sheet, failures dropped, never overwriting an existing analysis) — and a card whose tags came from that pass ends its `SceneTagLine` with a small sparkles glyph, updated in [projects.portrait.svg](projects.portrait.svg). The AI Models screen itself remains undrawn (🟡 in the table below) — it shipped unmirrored with the AI work and specifying it is its own unit. Verified on the iPhone 17 Pro sim (row rendering, badge, selection round-trip) and against real capture frames on the Mac (tags/elements/timings); Core ML cannot initialise inside the simulator, so classification itself was measured off-sim. Previous sync 2026-08-04 — **scene search on Projects**: the on-device analysis has been writing subject tags onto projects since the AI work landed, and nothing could be found by them. The Projects header now carries a search capsule (`SceneSearchField`) and a horizontal row of subject-tag chips (`SceneTagChips`) below the shared capture-kind filter; typed words match a project's name, its tags (raw *and* labelled, so "sky & weather" finds `skyWeather`) and the free-form elements the model named for the frame, with every typed word having to land somewhere — so each word narrows. Chips AND together. The analysis's `elements` are now persisted (`CaptureProject.sceneElements`, applied through `applySceneMetadata(_:to:)` taking a whole `SceneMetadata`) instead of being discarded with the proposal sheet, which is what makes "waterfall" a searchable term; they also surface as an **In frame** row on project detail. Analysed cards gain a `SceneTagLine` (≤3 chips then "+N") so the chips filter by something visible — that grows an analysed card by 14pt; an unanalysed card is unchanged. Empty state splits: a search or chip that matched nothing says what it looked for and offers **Clear filters**, while the kind filter alone keeps its "No videos" + Show all. Search and chips are both hidden while the library is empty, and the chip row is built only from tags present in the library. New spec content in [projects.portrait.svg](projects.portrait.svg); verified on the iPhone 17 Pro sim via `LL_TAB=projects LL_TAGS=demo` (chip filter, element-only match on "waterfall", no-match state). macOS and iPadOS have no Projects spec to restage. Previous sync 2026-08-03 (later same day) — **warp timeline trust-and-navigation pass** after tester feedback (fiddly pinch, accidental segments with no way back): every timeline edit now lands on a 30-deep undo stack behind `AppModel.updateWarp` (continuous gestures coalesce to one step; Cmd-Z / shake / three-finger-swipe bridge through the window's UndoManager; Undo chip in the warp-card header, "Added 1× stretch · Undo" toast after each carve); a pinch cancels and gates nomination/knob/handle drags so zooming can never carve; pinch is anchored under the fingers (`MagnifyGesture` ≥ iOS 17/macOS 14, playhead/centre fallback) with a min(20s, source) floor and travel-end ticks; ruler pan rewritten 1:1 base+delta on measured width (the old math compounded quadratically); a minimap lens strip appears while zoomed; an off-window playhead shows an edge chevron (tap recenters) and dims its thumbnail with a directional badge; the advertised hold-to-open stretch menu is real (0.45s, engage haptic, release-tap swallowed) plus a native right-click context menu on macOS; knob/handles/pills/chips got 44pt targets and knob/handle drags became relative (no jump-to-finger); the nominate overlay signals validity (grey-dashed → amber at 2s, tick on crossing, warning toast on a short release); double-tap zooms in/out (the macOS mouse path). New spec [adjust.zoomed.portrait.svg](adjust.zoomed.portrait.svg); verified on the iPhone 17 Pro sim via `LL_ADJUST=demo` (pinch-carve regression, nominate→undo round-trip, hold menu). The engine compiles stretches+seams into per-file window schedules (`WarpCompiler` → `VideoBlendOptions.customWindows`) — one pass for single-file sources, blur follows speed through eases, never a trim; the warp persists on the blend (`BlendProject.warp`). ## Collections

The Collections feature (2026-08-01): an ordered set of blended clips from across projects on one timeline — per-clip in/out trims (fractions of the clip; trims retime the cut, clips always butt together), per-ratio crops (single-axis pan offset; collection-local override → clip default → centred), canvas ratios 16:9 · 9:16 · 1:1 · 4:3 · 3:4 exporting at 3840×2160 / 2160×3840 / 2160×2160 / 2880×2160 / 2160×2880, and a kept render that makes re-export instant while the recipe (clips + trims + crops + ratio + fps) is unchanged. Data model: `LapseCollection` in `App/CollectionsModel.swift`, persisted in `library.json`; default crops live on `BlendProject.defaultCrops`. One appearance per clip per collection; stills locked out (v1 video-only); deleting a blend or project drops it from every collection (the delete alert names them).
